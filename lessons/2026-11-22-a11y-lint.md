# Accessibility lint rules on, 2026-11-22

## What

- Nine jsx-a11y rules that were off since the oxlint move are on: click-events-have-key-events,
  no-static-element-interactions, no-noninteractive-element-interactions, media-has-caption,
  label-has-associated-control, no-autofocus, no-redundant-roles, heading-has-content and
  no-noninteractive-tabindex.
- Real fix: `CardTitle` renders `{children}` itself instead of passing them through the spread,
  so its heading has visible content.
- `label-has-associated-control` is told that `HourSelect` is a control (`controlComponents`).
  It renders a native `<select>`, so the wrapping labels already worked.
- Kept, each with a disable comment and its reason:
  - The trailer's two tap layers. The touch one is the only way to toggle play on touch. The
    desktop one has Play/Pause, Mute and Exit buttons.
  - The carousel's focusable region with arrow keys, the WAI-ARIA carousel pattern.
  - `autoFocus` on the filter-name field and the player iframe. Both appear because the user
    just pressed something.
  - The breadcrumb's `role="list"`. Safari/VoiceOver drops list semantics from a
    `list-style: none` list without it.
- `prefer-tag-over-role` stays off for good. All 26 hits are correct roles on divs, and the tags
  it wants change the look or the behaviour.

## Mistakes

- None here; the wrong turns were in social-media-downloader's pass the same day (disable
  comments on the attribute line instead of the opening tag).

## What worked

- JSX block comments (`{/* oxlint-disable-next-line ... */}`) work for elements in children
  position. `--report-unused-disable-directives` proves each one is used.

## Rules

- Before obeying `no-redundant-roles` on a list, check its list-style. With `list-style: none`,
  the explicit role is the fix, not the redundancy.

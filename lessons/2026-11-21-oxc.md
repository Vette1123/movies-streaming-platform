# ESLint and Prettier to oxlint and oxfmt, 2026-11-21

## What

- `pnpm lint` is `oxlint --report-unused-disable-directives --deny-warnings`. `pnpm format` /
  `format:check` is oxfmt. CI and the `ci-gates` test now pin `format:check`.
- Removed eslint, eslint-config-next, eslint-config-prettier, eslint-plugin-react,
  @eslint/eslintrc, @typescript-eslint/parser, prettier, the ianvs import-sort plugin, and
  `.pnpmfile.cjs`. That file only existed to give typescript-eslint its own TS 6; nothing in the
  repo runs on TS 6 now.
- `.oxfmtrc.json` reproduces the ianvs import order with `sortImports` custom groups and
  `internalPattern: []`, and sorts Tailwind classes with `sortTailwindcss` against
  `styles/globals.css`. The one-time reformat touched 23 files, all whitespace or import order.
- `eslint-plugin-tailwindcss` still runs as an oxlint JS plugin: a canary fires shorthand,
  contradicting-class and canonical-class checks. It costs 10 of lint's 14 s; native rules alone
  take 3.7 s.
- New type-aware and correctness rules found real bugs:
  - `PageDetailsProps` typed `params` as a plain object, but Next 16 passes a Promise (6
    `await-thenable` hits).
  - `QUERY_KEYS` lacked `as const`, so both keys typed as `string`.
  - `ui-shots.mjs` split class names on the letter "s": `/\s+/` sat inside a template string, so
    the backslash was eaten. `cls-probe.mjs` matched "Search" plus any 3 characters the same way.
  - 11 floating promises.
  - 13 unused bindings, including a `contentType` in library ingest that was computed and never
    stored.

## Mistakes

- First oxfmt pass moved every `@/services` and `@/providers` import: oxfmt treats `@/` as
  internal, while ianvs treated unlisted aliases as third-party. 62 files changed. With
  `internalPattern: []`, 23 did.
- `@oxlint/migrate` turned `correctness` off again, same as social-media-downloader.

## What worked

- A throwaway `-c` config plus `--format=json` counted by rule, before any rule was chosen.
- Reading `no-useless-escape` hits in scripts instead of auto-fixing them. Both were regexes inside
  code strings, and the right fix was `\\`, not dropping the backslash.

## Rules

- `no-useless-escape` on a regex inside a template string is a bug report, not a style nit.
- The a11y rules switched off in `.oxlintrc.json` are a UI pass of their own. Turn each one on as
  its hits are fixed.

# h-6 is not 24px, and other things a screenshot cannot show

**Date:** 2026-09-01
**Scope:** an end-to-end sweep of every route for defects of any kind — visual,
behavioural, accessibility, structural.

## What

Walked every reachable surface in a real browser with a per-page DOM audit
rather than by eye: horizontal overflow, `img` with no `alt`, controls with no
accessible name, hit targets under 24×24, heading order, duplicate ids, missing
focus indicators. Routes covered: `/`, `/movies`, `/tv-shows`, both detail
shapes, `/collection/[id]`, `/person/[id]`, `/genre`, `/year`, `/people`,
`/lists`, `/stats`, `/start`, `/mood`, `/reels`, `/match-night`,
`/watch-together`, `/next-up`, `/watchlist`, `/watch-history`, `/support`,
`/privacy`, `/terms`, `/disclaimer`, 404, the ⌘K palette, the mobile drawer, and
all thirteen `/account` panels.

Shipped in three commits:

- `fix(account)` — a failed session refresh left the account page on skeletons
  forever.
- `fix(a11y)` — the 24px tap floor, the missing select focus ring, four heading
  gaps, the footer link column.
- `fix(a11y)` — the unnamed drawer plus four more undersized targets in the
  account console.

## Mistakes

**Two "production is broken" findings that were the harness.** `/tv-shows` on
production came back with no filter sidebar at all — no `<aside>`, no
`Sort by`, only the `MediaListFallback` placeholder — three times in a row,
across a reload. I got as far as checking the deploy SHA against `main` and
reading `filtered-media-content.tsx` line by line looking for the branch that
could drop an element whose sibling classes proved the branch was taken. A
screenshot showed the sidebar rendered and correct. The automated tab is
permanently `visibilityState: hidden`, which deprioritises hydration; a
`setTimeout` of three or four seconds is not long enough on a 2560-wide page,
and a screenshot forces the paint that the wait does not. **Take the screenshot
first, then query the DOM.**

The same blindness produced a second round of false positives: every rail
heading and every rail link on the homepage and the detail pages reported as
empty or unnamed. `innerText` returns `''` for a subtree the browser has skipped
under `content-visibility: auto`, which is most of a long page. `textContent`
does not. The audit used `innerText` for the first half of the sweep.

**Reported the `/start` taste picker as twenty-four buttons with no accessible
name.** They are named — each wraps a `BlurredImage` with the title as `alt` —
but the `<picture>` had not mounted yet at the moment the audit ran. Same root
cause as above, third variant.

**Chased a blank Sort-by dropdown for six tool calls before checking
production.** In dev the select trigger renders empty until the menu is opened
once; on production it shows "Most popular" immediately. Worth ten seconds of
comparison before reading Radix's internals.

**Nearly fixed the footer credits line.** "Built by X with Next.js, Tailwind
CSS, …" is a row of 15px links, and they are exempt: WCAG 2.2's target-size
criterion does not apply to a link inside a sentence. The site-links column
above it is not a sentence, and that one did need fixing. The distinction is the
whole rule, not a detail of it.

## What worked

**A DOM audit finds what a screenshot cannot.** Nothing on this list would have
been caught by looking at the page: a 22.5px chip, a select with no focus ring,
an `<h4>` that only exists while a pointer is on a poster, a dialog with no
accessible name.

**The 24px floor is a pixel value, deliberately.** `html[data-density='compact']`
sets the root to 93.75%, so a Tailwind spacing step is 3.75px and `h-6` — the
idiom you reach for when you want exactly 24 — is **22.5px** for anyone who
turned the preference on. Every "24px" target on the site was one and a half
pixels short. `.tap-target` in `styles/globals.css` sets `min-width`/`min-height`
in px so a display preference cannot shrink a minimum.

**Reading the code around a symptom found a bug the symptom did not name.** The
account page pulsing skeletons on localhost is expected — there is no Worker in
`pnpm dev`, so `/api/auth/refresh` 404s. But the gate was
`if (account.signedIn === undefined)`, and `markFailed()` deliberately leaves
`signedIn` undefined so a network blip can never downgrade a supporter. So any
non-401 failure in production — the 503 a deployment without `DB` returns, a
dropped request — bricked the page the same way. The copy for exactly this case
already existed one branch below and could never be reached.

**Every fix went into the shared thing.** The tap floor is one utility; the
close button is one exported class string that dialog and sheet share (they had
drifted to the same 15×15 glyph independently); the chip's `interactive` variant
absorbed a hover treatment that had been copy-pasted into three files and was
simply missing from two more.

## Rules

- **Screenshot before you audit.** The automated tab is `visibilityState:
hidden`; hydration and Suspense reveals are deprioritised and a `setTimeout`
  is not a substitute for forcing a paint. A "missing" element is the default
  explanation only after a screenshot agrees.
- **Use `textContent`, never `innerText`, in a page audit.** `content-visibility:
auto` makes `innerText` return `''` for anything off-screen.
- **Compare against production before reading a library's internals.** Dev-only
  behaviour is cheaper to rule out than to explain.
- **Never write `h-6` or `size-6` and call it a 24px target.** Use
  `.tap-target`. The Tailwind scale is rem and this app ships a density
  preference that moves the root.
- **WCAG 2.2's target-size exception is for links inside a sentence.** A column
  or row of standalone links is not a sentence, whatever the font size.
- **A `failed` flag is an answer.** Any gate that decides what to paint from
  "have we heard back yet" must treat "we heard back and it did not work" as
  settled, or the failure state is unreachable.
- **A `<h1>` on the happy path only is a page with no heading.** Check the error
  and empty branches of any route that early-returns a whole page.
